# RunnerScope codebase review — 18 October 2026

The requested Runner Monitor review applies to the current repository/product,
**RunnerScope**. The baseline was `a3749702f70dae361d297f5402247b08b2fdc435`
(1.3.19); the reviewed corrections ship as **1.3.20**.

## Scope and ownership

| Area | Review scope |
| --- | --- |
| Architecture | Core/provider/configuration ownership; Common boundary; GTK and Win32 controllers; shared UI contract; worker snapshots and lifetime |
| Source | GitHub projection/pagination, sign-in and process adapters, HTTP, persistence, systemd observation/actions, native rendering and selection |
| Dependencies | Exact Common gitlink; bundled cJSON identity/limits; pinned GitHub CLI archives; Common-owned font hashes; toolkit/platform linkage |
| Configuration | Schema, defaults, migration, number grammar, validation, token handling, private atomic publication and failure behaviour |
| Tests | Shared contracts, malformed API data, concurrency, native process fixtures, storage, service interpretation, graphical smoke and release-state recovery |

| Packaging/installers | Debian dependencies/architecture/install contents; native CPU/LTO/PGO build; dependency installation, tests and package identity |
| CI/releases | Linux and Windows qualification, native installer qualification, immutable tags, draft recovery, artifact reuse, checksums and live APT verification |
| Repository | Working/default/remote branches, open PRs, source layout, documentation and remaining tracked architectural work |

## Findings corrected

| Finding | Resulting change and evidence |
| --- | --- |
| Monitoring serialized cJSON parsing, but authentication bypassed its lock. Both paths wrote cJSON's process-global error record. | `core/json.c` now owns one bounded, UTF-8/lexical validation and parsing boundary. A concurrent four-worker regression exercises valid and invalid parsing. |
| Sign-in accepted JSON through weaker validation and first-match object lookup. Embedded NUL escapes or duplicate organisation fields could change interpreted identity. | Authentication uses the shared decoder and rejects ambiguous essential members. Fixtures cover NUL and duplicate identities. |
| First setup always started browser login when no organisation had been entered, even with an authorised existing session. | Discover organisation choices before qualifying session reuse; discard old discovery if new sign-in is needed. Existing-session/sole-organisation reuse is tested. |
| Linux settings/history I/O lived inside the GTK controller. History reads were unbounded; read/parse failures looked empty, and later events could replace the original file. | `platform/linux_storage.c` owns both stores without GTK. Settings are bounded to 64 KiB, history to 4 MiB/300 retained entries. Invalid reads preserve the original; new events remain in memory after failed history loading. Publication failures are surfaced. |
| Opening a FIFO as a settings file could block before file-type validation. | Nonblocking, no-follow regular-file reads reject special files and symlinks. Storage fixtures cover these cases without requiring a desktop. |
| Linux only checked its overall refresh deadline between requests. Cancellation did not reach an in-flight native transfer; Windows context implicitly meant a deadline pointer. | A documented `RunnerHttpOptions` contract carries deadline and cancellation. libcurl bounds each request by remaining time and supports cancellation; WinHTTP checks cancellation while waiting. Offline tests reject expired/cancelled requests before networking. |
| Two unused OAuth POST implementations and their public callback/API remained after the official broker replaced that flow. | Remove the dead path. Monitoring transports now implement the one supported HTTPS GET responsibility. HTTP policy fixtures test that actual path. The legacy config field remains for data compatibility. |
| Substring labels such as `not-self-hosted` and arbitrary `*-latest` names could be interpreted as hosting facts. Unknown active jobs were omitted from the active total. | Hosting classification uses exact labels/groups, leaves unsupported evidence unknown, and includes unknown active work in the total. Regression fixtures cover misleading labels. |
| Local service reads retained old data without independent stale state; substring correlation could assign `worker-2` to `worker` or another organisation. | Service observations have fresh/stale/error state and unavailable metrics after failure. Correlation requires a complete canonical organisation/runner unit identity; fixtures cover false partial and cross-organisation matches. |
| Windows retained selection by row index after replacing/reordering a snapshot. Large valid saved intervals overflowed during seconds-to-milliseconds conversion. | Restore selection by runner name, clear missing/filtered selection, update native layout/table selection, and clamp timer conversion using a wide intermediate. Native self-tests cover identity lookup and overflow. |
| Windows checked font resource presence but could silently substitute a system font after a load failure. | Check actual private font registration, remove the substitute-family fallback and fail explicitly if required fonts cannot load. The Windows self-test exercises registration. |
| NaN utilisation bypassed ordinary lower/upper clamps before native drawing. | The shared card contract maps non-finite utilisation to zero; tests cover NaN and both infinities. |
| Core tests required GTK and downloading desktop fonts/broker. Test targets ignored `BUILD_TESTING`; platform targets inherited GTK needlessly. | Split CMake core, native desktop, runtime assets and tests. Core-only builds need no desktop assets/platform libraries; test targets respect `BUILD_TESTING`. Linux adapters link GIO, while GTK belongs to the shell. |
| Failed downloads could poison archive caches, and every configure rewrote the extracted sign-in helper. An incremental-build check encountered a truncated extracted helper. | Downloads use verified partial files. Broker extraction is staged and records archive/binary identity; valid caches are reused, damaged/interrupted caches are replaced. The local damaged cache was repaired and requalified. |
| Debian advertised any architecture despite supplying an AMD64-only broker. curl's option-level runtime requirement was not expressed by symbol-derived dependencies. The product licence was absent from the install layout. | Declare AMD64 and curl >=7.85, retain the supported native targets, and install the product GPL text alongside existing third-party notices. |
| Native dependency installation omitted Git although Debian required it. Profile mismatch errors were weakened, and `nocheck` did not suppress the custom test override. | Install Git, make incompatible PGO coverage a build error, and honor Debian `nocheck`. Default qualification still runs both training and final tests. |
| A tag with an interrupted draft release was treated as already published. Overlapping workflow runs could race publication. | Testable release-state logic distinguishes draft/published/error states and retains immutable-tag enforcement. Workflow concurrency serializes runs per ref. Sanitizer/release-tool qualification is a release prerequisite. |

CI metadata checks consume complete command output before matching it, avoiding
quiet-consumer broken-pipe races. Forbidden dependency/linkage checks use explicit
failure branches, so Bash errexit exceptions for standalone negation cannot
silently accept a failed check. Licence qualification accepts Debian's normal
compressed `COPYING.gz` layout and validates that compressed file. Installed
package qualification lives in `support/release/verify-installed.sh`, where the
normal ShellCheck gate covers these checks as executable source. The initial
1.3.20 hosted Linux run built and tested the application successfully, then
caught the new check's uncompressed-file assumption before any publication.

## Validation

Local validation of the release candidate includes:

- seven core-only tests with AddressSanitizer and UndefinedBehaviorSanitizer;
- twelve native Linux CTest checks with the same sanitizers;
- the graphical GTK smoke test, including sign-in cancellation, automatic Settings save,
  cards/filtering, immutable worker credentials, stale-result rejection and corrupt
  history surviving new events and shutdown;
- ShellCheck and shell syntax checks for installer/release scripts;
- release-state fixtures for new, draft, published, unavailable, malformed and
  mismatched-tag cases;
- a successful core build with `BUILD_TESTING=OFF` and zero registered tests;
- GCC static analysis of the shared core/UI sources, with no diagnostics;
- CMake install staging and product/third-party notice checks; and
- workflow YAML/release dependency validation and `git diff --check`.

LeakSanitizer process inspection is unavailable in the local executor, so local
ASan runs disable leak detection. Hosted core sanitizer CI keeps the normal leak
checks enabled. Native Windows execution, exact Debian install/purge and the
full trained native installer are release gates on their supported CI hosts.

The release workflow publishes only artifacts qualified in that same run.
GitHub asset downloads/checksums and the beta/alpha APT index/package digest checks
remain required. A completed GitHub upload alone is not treated as completed
distribution publication. The baseline 1.3.19 failure was its APT wait, after all
native artifact qualification passed; the live index subsequently contained it.

## Boundaries and retained work

The exact Common gitlink is unchanged. Product policy remains local to
RunnerScope; no second Common version pin, alternate application or replacement
widget toolkit was introduced. The bundled cJSON files remain unmodified at the
recorded upstream 1.7.19 identity, which is the upstream latest release observed
during this review.

The existing Windows Active Jobs, History and Local Health feature gaps remain
explicit, as documented under issue #2. They are feature/parity work, not hidden
successful observations. Issue #14 retains broader controller/model decomposition:
the GTK controller is still substantial, and Win32 implementation slices still
share one private application translation unit. Persistence and parser ownership
are now real modules; completing the existing UI migration requires its own
native parity work and validation.

The existing TSV projection is retained as the provider/controller compatibility
boundary. A future typed model migration should remove that serialization seam
together across both renderers; this review does not claim that migration has
already happened. Custom/escaped service identities that cannot be correlated
unambiguously remain unknown. Live account authorization and actual runner
service restart are deliberately outside offline qualification.

At the review baseline, the repository already retained only `main` and had no
open PRs. The two open architecture issues describe real retained work and are
not closed as debris. Published historical tags/releases remain immutable.
